# Happy Bear Cozy Orchard — Enhancement Ideas

Brainstormed candidates for future work, not yet scheduled. Unlike `TODO.md`
(planned, in-progress, or already-shipped work), nothing here is committed to.
Check items off as they move into `TODO.md` and get built.

## Nearly free — scaffolding already exists, unused

- [x] **Achievements** — done. 24 milestones across progression/first-crafts/orchard/economy/building/time/land in `src/data/achievements.json`, evaluated by the new `AchievementSystem.js` against `ProfileSystem`'s existing (previously-unused) `unlockAchievement()` plumbing. Toast notification + a modal (🏆 button in the HUD) listing all 24 with lock/unlock state. Retroactive: loading a save that already qualifies for milestones credits them immediately instead of waiting for the next matching event. Caught a real ordering bug while building it — `resources.onChange` fires *before* handler-local stat counters (`gameStats.harvests++` etc.) update in the same click handler, so the achievement check needed explicit calls after those counters update, not just a listener on resource changes.
- [ ] **Storage / Cabin upgrades** — `docs/GameDesign.md` §7.2 specs "more tool slots, decorative items, larger production capacity" as a Cabin Upgrade category; never built. Resources also have no storage cap today, which removes a management layer the original design assumed (a Storage Shelves tool is named in `docs/GameDesign.md` §4.1 but doesn't exist in code).
- [ ] **Reorganize the Market into a logical order** (Jim's idea) — `store.json`'s item order today is just "whatever order things got added across sessions," not grouped by anything a player would recognize. Concretely: raw materials are scattered (`fruit` at the top, `wood`/`stone` all the way at the bottom, `cranberry`/`blueberry` stuck between them), the cider family is split across three non-adjacent spots (`bottles` near the top; `cranberry` + `bottled_autumn_hug` and `blueberry` + `bottled_cider_creek_blue` both tacked on near the end), and `hops` sits between the cider and distillery entries even though it belongs to the brewery line. Nearly free to fix: `StoreSystem.getItems()` and `store.js`'s `_renderSell()` already render whatever order the array lists, generically — no code change needed, just re-sequencing `store.json` itself (e.g. raw materials → cider family → distillery → brewery → roastery), or adding a `category`/`sortOrder` field if visual section headers in the Market are wanted too.
- [ ] **Make icons more meaningful and consistent, starting with bottled goods** (Jim's idea) — every bottled product should read as "the same *kind* of thing, different flavor," but right now each one is a different container shape: plain Bottled Cider is 🍾 (champagne bottle), Bottled Autumn Hug is 🍶 (a sake bottle — wrong shape entirely), Bottled Cider Creek Blue is 🫙 (a jar, not a bottle at all) — picked one at a time per-flavor across sessions rather than as a deliberate set. Real constraint worth flagging before starting: Unicode only has one properly bottle-shaped emoji that fits the vibe (🍾) — there's no second or third "bottle" emoji to give each flavor its own distinct-but-still-a-bottle icon, so a pure-emoji fix means using 🍾 everywhere and differentiating flavors some other way (background color per card, a small flavor-colored badge/dot, etc.), or moving those specific icons off emoji to small SVG/CSS shapes for real control. Worth a full pass over the *rest* of the icon set at the same time, not just bottles — e.g. `juice`(🧃)/`cider`(🫗)/`applejack`(🥃)/`whiskey`(🪣) each read fine in isolation but were never chosen as a deliberate palette either.

## Content depth using systems that already exist

- [ ] **More crops / flavor variants** — in progress. First flavor shipped: **Autumn Hug** (cranberry), see `docs/TODO.md`. Remaining: the multi-crop system (crop-aware `TileGrid`, per-crop `crops.json` entries) has apple/hops/coffee/timber/cranberry; `docs/GameDesign.md` §3.4 still names unused botanical zones (Peach Orchard, Cherry Grove, Blueberry Bend, etc.) and §8.1 still names more cider flavors (Creekside Watermelon, Sticky Paws Apple Caramel, ...) not yet wired to a recipe. The Autumn Hug slice established the pattern to repeat: new crop (free to plant, tier-gated) + the previously-unbuilt Flavor Table station (`docs/GameDesign.md` §4.1) blending bottled cider + the crop into a new premium sellable resource — cheap to extend to another flavor, since the station and pattern already exist.
- [ ] **Craft Soda line** — non-alcoholic production category speced in `docs/GameDesign.md` §8.7 (Soda Station, botanical-based flavors), unbuilt. Would diversify away from "everything is alcohol," which matters for a family-friendly game.
- [ ] **Seasonal cycle** — spring/summer/fall/winter (`docs/GameDesign.md` §9) with season-locked recipes/crops. The day counter and calendar already exist (`gameState.day`, `TICKS_PER_DAY`); this would mostly be gating logic on top, for replay variety.

## Bigger swings

- [ ] **Post-Tier-5 endgame** — progression hard-stops at "Master Roaster" (`progression.json` tier 5). Nothing beyond that today. Worth a prestige mechanic, a Tier 6, or just more deals/recipes to chase once maxed out.
- [ ] **NPC visitors / one-off requests** — dynamic income on top of the existing fixed 14-day distribution-deals system (`deals.json`, `MarketSystem.js`), for more variety than static contracts.
- [x] **Consumer demand + automated selling + shelf spoilage** (Jim's idea, shipped as one bundle 2026-08-16) — came up when Jim raised a real problem: once every crafting station is automated (the `auto_press`/`auto_bottling`/etc. upgrades plus Harvest Bell's auto-water/mine/harvest), there's nothing left to actually *do* except periodically hit Sell. See `docs/TODO.md` for the full implementation writeup — supply-pressure demand pricing, shelf spoilage on raw crops, and a trickling Auto-Sell (`auto_sell`/Market Broker upgrade) all shipped together and gate on the same tier (`ECONOMY_PRESSURE_UNLOCK_TIER = 3`) since they're designed to interact: demand pricing makes dump-selling costly, spoilage makes hoarding costly, and Auto-Sell is the tool that avoids both by trickling stock out gradually. Seasonal demand (the other half of the original idea, tied to the not-yet-built Seasonal Cycle) is deliberately deferred — this ships the season-independent half only.
- [ ] **Cross-device / cloud save sync** (Jim's idea) — came up when Jim asked how his iPad save and his son's save on a separate device would interact. Today there's no interaction at all, by construction: the game is 100% static (GitHub Pages hosting, no backend of any kind), and every profile + save lives entirely in that one browser's own `localStorage` (`ProfileSystem.js`, save data under `hbco_save_<profileId>_<slot>`). That's actually why two family members on two devices already just works with zero setup — separate devices means separate storage, no possible collision — but the flip side is there's no way to continue *the same* save from a second device, and clearing site data or going incognito loses everything with no backup anywhere. This is a different tier of work than everything else on this list: every other item is frontend-only, buildable as static code shipped to GitHub Pages as-is. Real sync needs actual new infrastructure — some form of account/identity (even something lightweight, like a short sync code rather than a full login) plus a real backend to store and serve profile/save JSON, since GitHub Pages can't run server logic itself. Worth scoping as its own project, not a quick add.
